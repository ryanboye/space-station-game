# Gate F Art Handoff: Facility-Scale Fixture Sprites

## What Exists Now

Every fixture below is fully wired: enum, module definition, facility-slot
descriptor, atlas key, footprint entry in the packer, `required-keys-v1.json`,
`sprite-spec.yaml` prompt, and a **procedural placeholder PNG** generated by
`tools/sprites/generate-content-placeholders.mjs`.

The placeholders are correct in size, alignment and depicted-position count.
They are not finished art. This document asks for the curated replacements.

Regenerate placeholders at any time with:

```bash
node tools/sprites/generate-content-placeholders.mjs
```

Repack and validate with:

```bash
npm run sprites:pack:no-verify && npm run sprites:validate:v1
```

## Hard Constraints

These are not style preferences — the pipeline enforces them.

- **Exact pixel size.** `64 × footprint_tiles` per axis. A file of any other
  size is resampled with nearest-neighbour into the frame and loses its grid
  alignment. Matching exactly hits the byte-exact copy path in `pack-atlas.mjs`.
- **Authored unrotated.** A 90° placement rotates the same frame at draw time.
- **Transparent margin ≥ 3 px on all four edges.** `validate-atlas.mjs` fails a
  key whose 1 px frame border exceeds `opaqueRatio 0.5` or
  `brightOpaqueRatio 0.22`.
- **Legible at 32 px per tile.** The atlas is authored at 64 px per tile but
  modules are baked into a cached layer at world resolution — 32 device px per
  tile regardless of zoom. Judge every sprite downsampled to half size.
- **State variants must read as silhouette, colour or frame changes.**
  Fine detail disappears at 32 px. The existing damaged-module decal
  (`render.ts` `drawModuleConditionDecal`) already learned this the hard way.

## The Contract That Matters Most

**Depicted positions are real reservations.** The simulation resolves each
fixture's slots from `src/sim/facility-descriptors.ts`, and a player's only
clue about capacity is the artwork. If the art shows five stools and the
descriptor has four, the fixture is lying.

Counts below are authoritative. Do not change them in art without changing the
descriptor and the runner in `tools/gate-f-facility-scale-tests.ts`.

## State Variants Requested

Same footprint and rules as the base key. Suffix is `module.<name>.<variant>`.

| Variant | Applies to | What it must communicate |
|---|---|---|
| `.active` | service_bar, bar_corner, bar_end, booth_bank, standing_rail, serving_line, community_table, guest_cabin, arrival_desk, wash_bank | In service right now. Occupied positions, working equipment. |
| `.unstaffed` | service_bar, serving_line, arrival_desk | Positions exist but nobody is behind them. The staff side should read as abandoned, not broken. |
| `.empty` | backroom_stock_bank, service_bar, serving_line | Out of stock. Shelves/glassware/hot line visibly bare. |
| `.dirty` | all eleven | Accumulated mess from real use. |
| `.damaged` | backroom_stock_bank, service_bar, bar_corner, bar_end, booth_bank, serving_line, community_table, wash_bank | Physically broken and needing repair. |

Connected-bar geometry is handled by the three separate bar modules rather than
by autotiled variants, following the existing dock-facade precedent. The art
must make a Service Bar + Bar Corner + Bar End read as **one continuous
counter** when placed adjacently — that is the whole point of the pieces, and
the simulation already treats them as a single provider run.

For key `module.service_bar`:

2. Nothing else. Footprint, required-keys, spec prompt and normalize entries
   are already registered.

If a footprint ever changes, update all four of:
`src/sim/balance.ts` (MODULE_DEFINITIONS), `src/sim/facility-descriptors.ts`
(slot coordinates), `tools/sprites/pack-atlas.mjs` (MODULE_FOOTPRINT_BY_KEY),
`tools/sprites/normalize-module-footprints.mjs` (FOOTPRINTS).

## Two Pipeline Warnings Found While Wiring This

1. **`generate-content-placeholders.mjs` overwrites three hand-authored PNGs.**
   `module_gangway.png`, `module_cargo_arm.png` and `module_bar_counter.png`
   are still listed in the script's original `assets` map, and any run replaces
   the high-resolution art with a low-fi SVG placeholder. They were restored
   from git after this work. Those three entries should be deleted from the
   map before anyone runs the generator again.

2. **`npm run sprites:pack` prunes tracked archives.** It chains
   `archive-atlas.mjs`, which keeps only the ten newest archive directories;
   running it repeatedly deletes tracked baselines under
   `tools/sprites/archive/`. Use `pack-atlas.mjs --profile v1` directly while
   iterating, and accept the prune only when you want a new snapshot.

```bash
npm run sprites:pack:no-verify && npm run sprites:validate:v1
```

Then load a showcase and look at the fixture at play zoom:

- `?scenario=market-compact-conflict` / `?scenario=market-improved-flow`
- `?scenario=cantina-undersized` / `?scenario=cantina-expanded`
- `?scenario=reception-absent` / `?scenario=reception-staffed`
- `?scenario=long-stay-guest-wing`

Count the depicted positions on screen and check them against the table above.
